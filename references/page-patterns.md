# Page patterns

Read this reference only when the content does not already imply a clear structure. Choose one primary pattern; borrow individual components without mixing several competing layouts.

- **Gallery:** masthead, concise introduction, optional filters, numbered sections, and a card grid with content-specific thumbnails.
- **Explainer:** narrow reading column, glossary or supporting rail, callouts, diagrams, and optional disclosure sections.
- **Plan or report:** document header, status summary, decisions, timeline, risks, and explicit next actions.
- **Code review:** change summary, file paths, annotated diff rows, call graph or module diagram, findings, and verification evidence.
- **Design reference:** tokens, component contact sheets, variants, accessibility notes, and usage guidance.
- **Presentation:** title, a sequence of focused sections, supporting evidence, one key takeaway, and next steps.
- **Custom editor:** compact controls, obvious state, live preview, keyboard operation, and a clear export affordance.

Use real source structure instead of forcing content into the chosen pattern. Metrics belong only when the source genuinely contains measurements.
